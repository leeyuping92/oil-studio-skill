# 缩放判断

用于"调整缩放"第 2 步：决定录屏里哪里推近、推多近、哪些现有缩放要改或删。返回 [SKILL.md](../SKILL.md)。

## 目标

观众始终看得清正在讲的东西，同时不被频繁推拉晃晕。缩放服务于讲解：讲到哪里、需要看清什么，就推近到哪里；讲概览、来回切换的时候保持全屏。

## 先理解，再动手

1. 通读 `utterances`，标出每段在讲什么：概览、操作某个控件、读一段文字或代码、看结果。
2. 对照 `activity`：点击、输入、滚动的时间和位置。
3. 对照 `zooms`：现有缩放在哪里、多大、来源（`origin`）。

## 该推近的

| 场景 | 推近方式 |
| --- | --- |
| 在小控件上点击或输入（设置项、表单、菜单） | 跟随点击（`mode: auto`），常规窗口 1.22–1.30 倍（紧凑小窗 1.15–1.20 倍） |
| 讲解屏幕上的小字、报错、代码、数值 | 固定位置（`mode: manual`），`target` 对准文字中心，1.30–1.50 倍；用 `frame --text` 找到文字位置 |
| 讲的东西和鼠标不在一处（嘴上讲右边的结果，鼠标停在左边） | 固定位置，对准讲的东西，不对准鼠标 |
| 停留在同一区域讲解 1.5–3.2 秒 | 保持推近，结束后拉回全屏留出呼吸感 |

## 不该推近或该删掉的

- **绝不让全片从头到尾一直处于放大状态**：每次推近持续约 1.5–3.2 秒后，必须拉回 `1.0x` 全景保持至少 1.8 秒，让观众看清整体界面响应；片头和片尾也应保留全屏概览。
- 讲概览、介绍整体布局、弹出居中大弹窗或在多个区域之间切换时，保持全屏。
- 连续滚动、拖动窗口时不推近，画面会晕。
- 同一局部区域内相隔不到 0.9 秒且总长不超过 3.2 秒的连续点击可合并为一个缩放；跨区域点击或已持续超过 3.2 秒时必须断开并拉回全屏。
- 推近后裁掉了正在讲或正在操作的东西：降低倍数（优先 1.25 倍左右）或改 `target`。
- 常规演示不超过 1.35 倍，除非用户明确要求看清极小的局部细节。

## 时机

- 推近在讲到那个东西**之前**约 0.3–0.5 秒开始，让镜头先到位；拉回在讲完之后。
- 每个缩放至少 1.5 秒；更短的不如不做。
- 过渡默认 `smooth`；只在需要突然强调时用 `instant`。

## 现有缩放

- `origin: user` 的缩放是用户亲手调过的：除非用户要求，不改不删；确实有问题时写进方案，Oil Studio 会默认不勾选并提醒用户。
- `origin: recorded` 是录制时按点击自动生成的，可以按上面的原则改、合并或删除。
- `visible: false` 的缩放整段落在被剪掉的部分，不用管。缩放跨过被剪掉的片段是正常的，按成片里可见的部分来判断。

## 写进方案时

- 每条写一句 `reason`，说明观众因此能看清什么，或者为什么删。
- 新增或改位置时，先用 `frame --zoom none --text` 看完整屏幕确定 `target`，提交前可以不带 `--zoom none` 再看一次效果（提交前看到的是现有缩放，接受后才是新效果）。
