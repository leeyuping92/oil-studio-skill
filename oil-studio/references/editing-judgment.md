# 剪辑判断

用于"精剪"第 2 步：决定一条口播录屏里删什么、留什么。返回 [SKILL.md](../SKILL.md)。

## 目标

剪完后观众听到的是一遍讲清楚、没有重复和磕绊的讲解，同时不丢任何信息、不打断正在演示的操作。拿不准时补证或明确列为待复核，不能用“保守”代替逐项判断。你就是语义判断者：命令行只提供证据和执行，不会替你决定删什么。

## 先通读，再判断

1. 从头到尾读完全部 `utterances`，弄清这条视频在讲什么、分几段；同时读 `screen`，知道每段在演示什么。
2. 再逐段找候选。不要边读边删：后面的内容经常决定前面那句是不是被重说了。

## 用好声音和画面证据

- `audio.unrecognized` 是有人声却没识别出字的地方，常是"呃、嗯"或含糊的半句；`audio.confidence` 低的句子文字可能不准，判断前看前后文。语速突然变慢、响度明显变低的句子，常是自言自语或想词的过程话。
- 识别文字可能把专有名词听错，别因为文字不通顺就当成口误；需要时看屏幕文字。
- 对每个拿不准的候选，用 `oilstudio storyboard <工程> --utterances <起>-<止> --out <png>` 看一张图：画面、声音波形和每个字的位置都在上面。波形有起伏下面却没字，是没识别出的口头禅或含糊话；两遍话的波形相似、前一遍断断续续，常是重说；一段操作有没有在后面重做，看上排画面。先用文字通读全片找候选，只对候选附近出图，不要整条视频逐段出图。
- 你能处理音频时，可以用 `oilstudio audio` 导出那一小段原声听一下。

## 重说候选按这个顺序判断

1. 前后说的是不是同一件事，而不是恰好用了相似的词。
2. 后一遍是否明确覆盖了前一遍的全部信息。
3. 要删的部分有没有独有的提醒、条件、数字、警告、结果或操作。
4. 同一时间画面上有没有点击、输入、状态变化、结果展示，或者在请观众看某样东西（查 `activity`，需要时用 `oilstudio frame` 看画面）。
5. 删掉后把前后两句连起来读：主语、转折和意思是否完整。

任何一步答不清，就保留，或标成 `review`。

## 应该删的

| 类别 | 判断标准 |
| --- | --- |
| `abandoned_take` 重说的前一遍 | 后面有一遍明确重说了同一件事，并完整覆盖前一遍的信息。删前一遍，留后一遍，并在 `keptRange` 写出后一遍的发言编号 |
| `false_start` 说到一半放弃 | 一句话没说完就停下，紧接着换了说法重新开始 |
| `slip` 口误 | 说错后立刻自我纠正（"是三个，不对，是四个"）：删错的部分和纠正词，留正确的说法 |
| `filler` 犹豫音与无关话 | 无词义的“呃、嗯、um、uh”等可分离声音，或与讲解无关的闲聊、自言自语；按下节逐项判断 |

## 不能作为删除理由的

- 停顿本身：停顿不能证明前后是重复。空白交给"收紧停顿"。
- 文字相似、关键词重合、句子长短：相似不等于重说。
- 出现在句中、时长很短、没有两侧静音，都不能单独作为保留或删除口头禅的理由。句法位置不等于声音是否连读；按词义、真实词级边界和接缝判断。

## 中英文口头禅：逐项复核

标准精剪包含去除可独立切开的犹豫音，不必等用户再说“去水词”。按以下顺序审完当前保留画面内的全部 `fillerCandidates`，不能只挑长音或前几项：

1. **读完整上下文，判断是否有词义。** 无词义的“呃、嗯、um、uh”等优先建议删除；句中的“这个呃工具”也可以删“呃”。“啊”可能是犹豫音，也可能承载应答、强调或语气，分别判断。“那个、就是、然后”和 like、so、you know、I mean、actually、basically 可能表达指代、因果、比较、澄清或时间承接，不按词表批删。
2. **核对词级范围与接缝。** 参考 `suggestedCuts`、前后词时间和波形；范围只能覆盖无词义声音及必要气口，不截掉相邻词、辅音、缩写或有效音节。无需强求两侧都有静音；确有连读且切开会伤字时保留或补证。不能设置“只删超过某时长”的统一筛选，也不能把短候选一律留待复核。
3. **检查操作与未识别人声。** 与操作重叠时按下节保护画面，不为了删一个音丢掉关键点击或状态。转录缺词不等于静音；只对可疑区间看证据，不整片逐秒出图。
4. **给每项结论。** 写 `cut`、`keep` 或 `review` 和具体理由。整段重说删减已完整覆盖它时记为已覆盖，不另加重复切口。`review` 要说明缺的是哪项证据或哪个相邻词有风险，不能只写“句中”“太短”“检测要求复核”。保守风格也要记录按用户偏好保留的候选。

`group: certain` 是检测提示，不保证自然；`possiblyMeaningful`、`requiresReview` 表示需要你判断，不是永久保留指令。对没有词义、边界清楚的词不要只因检测标记放弃处理。无法理解音频时，仍要结合词级时间、波形和上下文逐项判断；确有证据不足的接缝才标复核，并明确未试听，不伪造听感。

英文只匹配完整的 um、uh、er、ah，不在 summer、other 等词内删除字母；忽略大小写，保留缩写，不跨句号或明显停顿拼词组。旧版缺 `fillerCandidates` 时用已有词级转录人工检查，不重新转录。

覆盖检查见[提案格式](proposal-formats.md)；它只证明每项有去向，不证明切口自然或修改已生效。应用后须重新读取当前保留部分，核对接受条目的实际残留。保留和待复核项要汇报，不能隐藏成“已清理完成”。

## 必须留的

- 只出现一次的信息：数字、版本、名称、步骤、条件、提醒、警告、结论、结果。
- 前后两遍相似但后一遍没有完整覆盖前一遍时，两遍都留，或把前一遍标为 `review`。
- 正在演示操作的片段，除非后面完整重做了同一个操作（见下一节）。
- 最终保留版本的开场、问候、自我介绍和结尾总结；重录的早期版本不因带有问候或总结而全部保留。用户要求“以最后一遍为准”时，优先保留最后一次完整表达，并核对独有信息。

## 和画面操作重叠时

要删的范围与 `activity` 里的点击、键盘、画面变化重叠时，默认这段操作是需要的，Oil Studio 会把这条删减默认设为不勾选。只有你看过画面、确认这个操作在后面被完整重做或与讲解无关时，才在这条决定里写 `screenAction: "redundant"` 和一句 `visualAssessment`（例如"同一个设置在 U0031 处重新演示了一遍"）。没看画面就不要写。

## 转折处要复核

被删的话以"但是、不过、然而、可是、也就是说、所以、因此、另外、同时、虽然"开头，或删掉后下一句以这些词开头时，以及英文 but、however、although、so、therefore、in other words、also、meanwhile 附近，把前后连起来读一遍，确认逻辑仍然成立；拿不准就标 `review`。

## 风格

| 风格 | 删的范围 |
| --- | --- |
| 保守 | 只删重说的前一遍和说到一半放弃的话，置信度都要 high |
| 标准 | 再加上口误、可独立切开的口头禅和明显的无关话 |
| 紧凑 | 再加上重复强调、绕远的铺垫；仍然不删任何独有信息 |

## 写进方案时

- 每条删减写清 `removedText`（被删的原话）、`keptText`（保留下来覆盖它的原话，没有就留空）、`reason`（一句话）。
- 范围尽量用发言编号；只删一句话中间一部分时，用词级时间取出 `sourceMs`。
- 单条删减超过 30 秒时，在 `reason` 里说明为什么整段都能删；Oil Studio 会把它默认设为不勾选。
